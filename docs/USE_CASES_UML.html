User Registration & Authentication

Actor: Visitor / User AWS Cognito API Gateway All Tiers

Users authenticate via AWS Cognito using OAuth social login (Google/GitHub) or email/password. A JWT access token is issued and attached to every subsequent API request. On first login, users are redirected to the onboarding flow. Suspended accounts receive a blocked-account error and cannot proceed.

F-04

Job Filtering & Matching Algorithm

Actor: System (Internal) Scoring Engine DynamoDB

Before serving jobs to the user, a multi-component scoring algorithm (0–100) ranks each job. Score components: Role match (keyword mapping across 15 categories), Experience level (Junior/Mid/Senior/Student detection), Distance (Haversine formula: 10 km = 40 pts, 80 km = 0 pts). High-scoring jobs form the "primary pool"; the rest form the "discovery pool".

Implements: lambdas/jobs/handler.py — score_job(), haversine(), ROLE_KEYWORDS
sequenceDiagram participant JL as jobs Lambda participant DB as DynamoDB participant GEO as Nominatim (Geocoding) JL->>DB: Fetch all active jobs DB-->>JL: Job list loop For each job JL->>JL: role_score = match(userRole, job keywords) [0-60] JL->>JL: exp_score = match(userExp, title/desc) [0-20] JL->>JL: dist_km = haversine(userLat/lng, jobLat/lng) alt dist_km <= 10 JL->>JL: dist_score = 40 else dist_km <= 30 JL->>JL: dist_score = 30 else dist_km <= 50 JL->>JL: dist_score = 20 else dist_km <= 80 JL->>JL: dist_score = 10 else JL->>JL: dist_score = 0 end JL->>JL: total_score = role + exp + dist JL->>JL: Tag as PRIMARY (score >= 60) or DISCOVERY end JL->>JL: Sort primary DESC, append discovery JL-->>JL: Return ordered job list

F-05

Swipe Recording — Like & Pass

Actor: User swipes Lambda DynamoDB · SQS All Tiers

When a user swipes RIGHT (LIKE), an application record is created with status pending. If Auto-Apply is enabled (PREMIUM+), a message is pushed to the SQS auto-apply queue. A PASS swipe records the decision without creating an application. A race-condition guard prevents duplicate swipes on the same job.

Auto-Apply Automation (ECS Fargate + Playwright)

Actor: System / User (PREMIUM+) ECS Fargate · Playwright SQS · SES · S3 PREMIUM / PREMIUM_PLUS

Daily Swipe Quota Enforcement

Actor: User / System swipes Lambda DynamoDB FREE: 5  |  PREMIUM: 30  |  PREMIUM_PLUS: ∞

Each tier has a daily swipe limit enforced at the Lambda level. FREE = 5, PREMIUM = 30, PREMIUM_PLUS = unlimited. The counter resets daily at midnight UTC. When a quota is reached, the frontend shows a LimitModal with an upgrade prompt. Failed auto-applies are refunded (quotaExempt flag) so users are not penalised.

A scheduled Lambda (via EventBridge) uses the Telethon library to read new job postings from a curated Telegram channel. Each post is parsed for title, description, company, location, and apply URL.
